Encoding is converting human-readbale characters into bytes

Think: English → numbers

Where as, Decoding is converting bytes back into numbers

Think: numbers → English

When you write code:


You type:

Hello

Your editor encodes it into bytes and stores it on disk


When the browser reads the file:

It reads bytes like:

72 101 108 108 111

Then decodes them back and shows:

Hello

What exactly is really UTF-8?

UTF-8 is a rule book that defines how characters (represented as Unicode numbers or code points) encode into bytes stored in the disk in the writing phase (by the editor) and how the bytes stored in the disk decode into characters in the reading phase (by the browser).

Simply put, UTF-8 is a rulebook that defines how Unicode code points are encoded into bytes and decoded back into characters.

It uses 8-bit units (bytes) and uses between 1 and 4 bytes per character.


Important idea

Computers store bytes. What we see as "characters" are just interpretations of those bytes the computer stores

What if charset is removed?

The browser falls back to a decision chain:

  1. HTTP headers
  2. Byte Order Mark (BOM)
  3. Guessing
  4. Default encoding

This can lead to incorrect text rendering and inconsistent results across browsers and systems

Where ASCII, Unicode, and UTF-8 fit

  • ASCII said "let us assign numbers to a small set of characters"
  • Unicode came and said "let us assign numbers to ALL characters globally"
  • UTF-8 said "let us define how those numbers (assigned to characters i.e. Unicode numbers) encode into one or more bytes (each byte is 8 bits)"

Humans and engineers were the ones who assigned numbers to characters.

And these assignments are called encoding standards:
  • Character encoding (Unicode) → assigns numbers
  • Encoding format (UTF-8) → turns numbers into bytes

Bits and Bytes

  • A bit is a 0 or 1
  • A byte is 8 bits
  • A byte can represent values from 0 to 255

Final idea

  • Files are stored as bytes.
  • Meaning comes from how those bytes are decoded.
